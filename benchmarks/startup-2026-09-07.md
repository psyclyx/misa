# Startup phase baseline

Source: `ee6a6b9`, plus the startup probe in this commit. Run from the repository
root with `python3 benchmarks/startup.py --samples 10`. The runner emits phase
summaries, per-file compilation medians, raw samples, and a semantic-output hash.
No builds or other agent workloads ran concurrently; CPU affinity and OS cache
state were not controlled. Each sample starts a fresh LuaJIT process.
Toolchain: LuaJIT `2.1.1785763465`, x86_64; Python `3.13.12` orchestrated the runs.

The probe loads the default profile, performs setup and one `app/start` dispatch,
then commits its state. It **does not execute emitted native effects**: no provider
requests, credential checks, persistence, terminal startup, or asynchronous
completion processing. It uses the bundled compiler with static global checks
disabled and evaluates generated Lua; this is phase attribution, not an installed
binary's time-to-first-frame benchmark. Total includes source IO, JSON handling,
and uninstrumented bookkeeping; JSON-extension setup is included only in total.

Ten samples produced one identical semantic result (effects, view, model count,
command count), SHA256:
`c1a1d5ebcbffd618ba271af75c7da75f9f9014958649a70bd76d0ebe0d3a3d5e`.

Compilation accounts for roughly 96% of measured CPU time. The largest individual
compilation medians were messages (34.72 ms), framework (30.64 ms), agent (26.67
ms), and choices (23.79 ms), but the cost is spread across the profile. Optimizing
setup callbacks cannot remove this dominant cost. Next experiment: build-time
compilation of bundled sources, preserving dynamic Fennel for custom extensions.
No runtime optimization or speedup is claimed by this baseline.
